# 第一部分：三天学习安排

目标：三天内做出一个能移动、能交互、带状态栏和对话框的二维 ASCII 房间，并真正理解底层窗口模型。

核心实操约 5 小时，可以一次完成，也可以三天各学 1.5–2 小时。章节末扩展练习不计入这 5 小时。

## 第一天：先跑起来，再理解舞台

阅读：

- [[02_第一次运行与场景结构]]
- [[03_终端窗口与三种分辨率]]

操作：

1. 创建并运行 Modular Demo。
2. 从空 Scene 手动接好 `TerminalDisplay + TerminalModuleHost`。
3. 建立两个自由布局窗口。
4. 切换两种 Terminal 分辨率，比较固定 Surface 与自动 Surface。

当天成果：能解释屏幕像素、Terminal 分辨率、Window Surface 的区别。

预计 1.5 小时。

## 第二天：写自己的模块和 UI

阅读：

- [[04_编写第一个游戏模块]]
- [[05_字符绘图_UI与对话框]]

操作：

1. 完成 `HelloTerminalModule`。
2. 加入透明 HUD、边框、文本和 SubCanvas。
3. 做一个可显示/隐藏的高层对话框。
4. 退出 Play Mode，确认窗口和资源正确清理。

当天成果：不直接操作 Shader，也能用模块接口构建完整字符 UI。

预计 1.5 小时。

## 第三天：让它成为游戏

阅读：

- [[06_输入_状态与动态布局]]
- [[07_制作可玩的二维ASCII地图]]
- [[第一部分_完整编程示例]]

操作：

1. 实现 WASD/方向键移动与输入消费。
2. 实现墙、门、物品和交互。
3. 加入右侧状态面板和事件日志。
4. 用 Tab 改变布局，用 R 改变终端分辨率。
5. 完成第 7 章验收清单。

当天成果：一个最小但真正可玩的 ASCII 房间。

预计 2 小时。

## 时间不足时怎么删

优先保留：第 2、3、4、6、7 章的实际操作。

可以暂缓：SubCanvas 练习和 Fog of War。不要跳过三种分辨率，否则后续 Raster、视频和布局问题会很难排查。

## 三天后的自检

不看教程回答：

1. 一个游戏模块如何获得终端能力？
2. 为什么窗口位置与 Surface 分辨率必须分离？
3. 为什么输入应先改变状态，再绘制字符？
4. 为什么透明 HUD 必须使用透明背景语义？
5. 终端分辨率改变后，模块要重新处理哪些内容？

五题能清楚回答四题，并完成可玩房间，就可以进入第二部分。
