# 04 编写第一个游戏模块

## 为什么需要模块

直接从任意脚本寻找 `TerminalDisplay` 并写窗口，很快会出现生命周期混乱：窗口谁创建、谁更新、场景退出时谁释放？模块协议把这些问题压缩为四个明确入口。

## 完整脚本

在你自己的项目中创建 `Assets/Game/Runtime/Terminal/HelloTerminalModule.cs`。文件名必须和公开 MonoBehaviour 类名一致。

```csharp
using AsciiTerminal;
using UnityEngine;

public sealed class HelloTerminalModule : TerminalModuleBehaviour
{
    private TerminalModuleContext _terminal;
    private TerminalWindow _window;

    public override string ModuleId => "game.hello";

    public override void OnTerminalOpen(TerminalModuleContext context)
    {
        _terminal = context;
        _window = context.OpenWindow(
            "main",
            new Rect(0.1f, 0.1f, 0.8f, 0.8f),
            new Vector2Int(80, 30),
            layer: 0);

        DrawStaticContent();
    }

    public override void OnTerminalFrame(TerminalFrameContext frame)
    {
        if (_window == null)
            return;

        string clock = $"TIME {frame.ElapsedTime,6:0.0}";
        _window.Canvas.Write(2, 2, clock, TerminalStyle.Default);
    }

    public override bool OnTerminalInput(TerminalInputContext input)
    {
        if (input.Kind == TerminalInputKind.Character &&
            char.ToLowerInvariant(input.Character) == 'c')
        {
            _window.Canvas.Clear(TerminalStyle.Default);
            DrawStaticContent();
            return true;
        }

        return false;
    }

    public override void OnTerminalClose()
    {
        if (_window != null)
        {
            _terminal.CloseWindow("main");
            _window = null;
        }
    }

    private void DrawStaticContent()
    {
        TerminalCanvas canvas = _window.Canvas;
        canvas.Clear(TerminalStyle.Default);
        canvas.DrawBox(
            new RectInt(0, 0, canvas.Width, canvas.Height),
            TerminalStyle.Default);
        canvas.Write(2, 4, "HELLO, TERMINAL", TerminalStyle.Default);
        canvas.Write(2, 6, "PRESS C TO CLEAR", TerminalStyle.Default);
    }
}
```

把脚本加到 `TerminalModuleHost` 所在对象，进入 Play Mode。

## 必须读懂：ModuleId 与局部窗口 Id

模块写的是局部 Id `main`，实际全局 Id 会变成：

```text
game.hello.main
```

这是 `TerminalModuleContext.GetWindowId` 自动完成的。因此不同模块都可以拥有自己的 `main`，但不同模块本身的 `ModuleId` 必须唯一。

## 四个生命周期入口

| 方法 | 时机 | 适合做什么 |
|---|---|---|
| `OnTerminalOpen` | Host 打开模块 | 建窗口、申请 Binding、初始化状态 |
| `OnTerminalFrame` | 每帧 | 动画、定时器、按状态更新画面 |
| `OnTerminalInput` | 输入到达 | 修改状态并决定是否消费输入 |
| `OnTerminalClose` | Host 关闭模块 | 关窗口、Dispose Binding、退订事件 |

不要在 Unity `Start` 中假设 Terminal 已经准备好；使用 `OnTerminalOpen`。

## 每帧重画还是按需重画

示例只重写一小段时钟。静态边框放在 `DrawStaticContent`，不必每帧重画。真实项目建议：

- 状态变化时设置 `_dirty = true`；
- `OnTerminalFrame` 只在 dirty 时重画 UI；
- 连续动画只更新发生变化的区域；
- 多次写入时由 Canvas/Surface 批处理。

## 资源所有权

只要模块创建了资源，就应在关闭时释放：

```text
OpenWindow        → CloseWindow
BindRaster        → binding.Dispose()
BindWindowPostFx  → handle.Dispose()
事件 +=           → 事件 -=
注册能力/处理器    → registration.Dispose()
```

## 验证清单

- Console 没有脚本加载或重复 ModuleId 错误；
- 窗口边框完整；
- 时间每帧更新；
- 按 C 后重新绘制；
- 退出 Play Mode 时无异常；
- 暂时禁用模块后不会留下孤立窗口。
