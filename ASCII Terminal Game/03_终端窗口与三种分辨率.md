# 03 终端窗口与三种分辨率

## 从一个常见错误开始

你把终端设为 `400×200`，以为游戏会输出 400×200 像素；或者把窗口 Surface 设成 40×20，发现字符被放大，于是误以为渲染坏了。根因是系统同时存在三种分辨率。

## 三种分辨率

| 层级 | 示例 | 控制什么 |
|---|---:|---|
| 屏幕像素 | 1920×1080 | Game View/显示器上的真实像素 |
| Terminal | 160×90 或 400×200 | 整个假终端横竖可放多少字符格 |
| Window Surface | 80×45 | 某个窗口内部保存多少字符格 |

它们的关系不是相等，而是采样与缩放：

```text
Window Surface 字符格
        ↓ 映射到
TerminalWindow.Bounds 占据的终端格区域
        ↓ 字体/合成
屏幕像素
```

## Normalized Bounds

窗口布局用归一化 `Rect`：

```csharp
new Rect(x比例, y比例, 宽度比例, 高度比例)
```

`new Rect(0f, 0f, 1f, 1f)` 是全屏；`new Rect(0f, 0f, 0.7f, 1f)` 是左侧 70%。这里的 y 从终端布局顶部方向理解最直观，具体换算由 `TerminalLayout.ToCellRect` 完成。

相邻窗口应共享同一个分割值：

```csharp
float split = 0.72f;
Rect left = new Rect(0f, 0f, split, 1f);
Rect right = new Rect(split, 0f, 1f - split, 1f);
```

不要分别写 `0.72` 和 `0.28` 后再独立修改，否则容易留下缝隙或重叠。

## 两种 OpenWindow

### Surface 自动等于窗口格数

```csharp
TerminalWindow full = context.OpenWindow(
    "main",
    new Rect(0f, 0f, 1f, 1f),
    layer: 0);
```

适合清晰的 UI 与地图。终端分辨率变大后，如果你重新应用布局并同步 Surface，内部可绘制字符也会增多。

### Surface 独立分辨率

```csharp
TerminalWindow lowResScene = context.OpenWindow(
    "scene",
    new Rect(0f, 0f, 0.75f, 1f),
    new Vector2Int(60, 45),
    layer: 0);
```

适合故意放大的低分辨率地图、视频或 3D Raster。无论它在终端占多大区域，内部始终只有 60×45 个采样格。

## Layer 与透明背景

`Layer` 越大越靠上。同层时创建顺序参与排序。一个典型结构可能是：

```text
Layer 0   世界/Raster
Layer 20  HUD
Layer 50  对话框
Layer 100 暂停菜单或故障覆盖
```

叠加窗口如果使用不透明黑色背景，会遮住下层。只想显示字符时使用：

```csharp
TerminalStyle.Transparent
```

或者自己创建带 `TransparentBackground` 标志、背景 Alpha 为 0 的样式。

## 运行时改变布局

```csharp
context.SetWindowLayout(
    window,
    new Rect(0.05f, 0.1f, 0.9f, 0.8f),
    matchSurfaceResolution: false);
```

- `false`：只改变窗口在终端上的占比，Surface 不变，字符会缩放；
- `true`：Surface 同步为新的窗口格数，适合清晰 UI，但旧内容可能因 Resize 改变。

## 改变整个终端分辨率

```csharp
context.Terminal.SetResolution(
    400,
    200,
    TerminalResizeMode.ScaleWindowBounds);
```

`ScaleWindowBounds` 会按比例缩放已有窗口边界。改变分辨率后，仍建议模块重新应用关键布局，尤其是需要相邻边缘严格对齐时。

## 实验

创建一个左 70%、右 30% 的布局：

1. Terminal 先用 160×90。
2. 左窗口 Surface 使用 56×45，右窗口自动匹配。
3. 改成 400×200。
4. 分别尝试 `matchSurfaceResolution` 为 `false` 和 `true`。
5. 记录字符大小、可绘制范围和布局边缘的变化。

## 常见误区

- `400×200` 不等于输出视频像素；它意味着最多约 80,000 个终端格。
- 窗口 Rect 不决定内部 ASCII 细节；Surface 才决定。
- 低分辨率 Surface 被放大不一定是错误，可能正是红白机/古早终端风格。
- 固定左右分屏不是系统限制；窗口数量、位置和占比完全由模块或演出数据决定。
