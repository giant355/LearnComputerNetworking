# 06 输入、状态与动态布局

## 核心原则

输入不应该直接“画一个角色”。输入先改变游戏状态，绘制函数再把状态投影成字符。这样存档、重放、AI 控制和测试都能复用同一逻辑。

```text
TerminalInputContext → 修改状态 → 标记 dirty → Draw(state)
```

## 处理按键与字符

```csharp
public override bool OnTerminalInput(TerminalInputContext input)
{
    if (input.Kind == TerminalInputKind.KeyDown)
    {
        if (input.Key == KeyCode.Escape)
        {
            _paused = !_paused;
            _dirty = true;
            return true;
        }
    }

    if (input.Kind == TerminalInputKind.Character)
    {
        switch (char.ToLowerInvariant(input.Character))
        {
            case 'w': TryMove(0, -1); return true;
            case 's': TryMove(0, 1); return true;
            case 'a': TryMove(-1, 0); return true;
            case 'd': TryMove(1, 0); return true;
        }
    }

    return false;
}
```

旧 Input Manager 下，Host 可以自动产生这些事件。新 Input System 下，在 Action 回调里转发：

```csharp
moduleHost.SendInput(TerminalInputContext.FromKey(KeyCode.Space, true));
moduleHost.SendInput(TerminalInputContext.FromCharacter('e'));
```

## 输入消费

Host 按模块顺序转发输入。某模块返回 `true` 后，表示事件已经被消费，后面的模块不再处理。暂停菜单和对话框通常应位于更高优先级，并在打开时消费移动键。

不要让所有模块都直接读取 Unity 全局 Input，否则消费规则会失效。

## 状态驱动绘制

```csharp
private Vector2Int _player = new Vector2Int(4, 3);
private bool _dirty = true;

public override void OnTerminalFrame(TerminalFrameContext frame)
{
    if (!_dirty)
        return;

    DrawWorld();
    DrawHud();
    _dirty = false;
}

private void TryMove(int dx, int dy)
{
    Vector2Int next = _player + new Vector2Int(dx, dy);
    if (IsWalkable(next))
    {
        _player = next;
        _dirty = true;
    }
}
```

必须读懂：`_player` 才是事实，屏幕上的 `@` 是事实的可视化结果。存档保存 `_player`，不应把“屏幕第 4 格是 @”当作唯一游戏状态。

## 动态布局

布局状态同样先保存，再统一应用：

```csharp
private bool _showInspector;

private void ApplyLayout()
{
    float mapWidth = _showInspector ? 0.68f : 1f;
    _terminal.SetWindowLayout(
        _map,
        new Rect(0f, 0f, mapWidth, 1f),
        matchSurfaceResolution: false);

    _inspector.Visible = _showInspector;
    if (_showInspector)
    {
        _terminal.SetWindowLayout(
            _inspector,
            new Rect(mapWidth, 0f, 1f - mapWidth, 1f),
            matchSurfaceResolution: false);
    }
}
```

系统不预设“左 3D、右状态栏、下对话框”。这里只是你的一个布局状态；任何窗口都能独立移动、改变占比或暂时成为全屏。

## 分辨率改变后的处理

如果游戏允许切换 160×90 与 400×200：

1. 调用 `SetResolution`；
2. 再调用 `ApplyLayout`；
3. 根据需要决定是否 ResizeSurface；
4. 让各窗口重画；
5. 检查 Raster/后处理 Mask 是否仍覆盖预期区域。

## 实践任务

- `Tab` 开关右侧检查面板；
- 对话框打开时消费 WASD；
- `R` 在两种终端分辨率间切换；
- HUD 空白透明；
- 每次状态变化只触发一次重画。
