## 6. 最终总结

请用 3–5 句话描述这个 Lab 怎样体现 IP 的“尽力而为数据报服务”。

这个 Lab 中，每个 `Datagram` 都作为独立的数据报被路由器处理，路由器只根据目标 IP 和路由表决定下一跳，不保证它最终能够到达。若找不到匹配路由、TTL 减到 0，或输出接口队列已满，数据报就会被直接丢弃。路由器不会替它重传，也不保证数据报按序到达或只到达一次。因此，这个 Lab 体现了 IP 的“尽力转发，但不承诺可靠交付”。

### 实现问题

问题位于：

```cpp
queues_[tmp->interface_index].push_back(
    OutboundPacket{routes_[tmp->interface_index].next_hop, datagram}
);
```

`tmp->interface_index` 是**出口队列索引**，不是“匹配路由在 `routes_` 中的下标”。`tmp` 已经指向 `find_route` 找到的那条路由，下一跳也必须来自这条匹配路由。

当前公开测试恰好只用了“第一条路由、接口 0”等对齐场景，所以没有暴露这个错误。当路由顺序与接口编号不一致时，就会选择另一条路由的下一跳；接口编号大于路由数量时还可能越界。

请修正后增加或自行推演一个场景：先加入一条走接口 1 的无关路由，再加入目标路由且让它走接口 0，最终下一跳仍必须来自目标路由。
